# Менеджер лицензий

Сервер на FastAPI и PostgreSQL выпускает лицензионные ключи с заданным лимитом устройств. Клиентский скрипт на Python отправляет зашифрованный запрос на активацию и выводит результат.

[Демонстрация на видео](https://disk.yandex.ru/i/7GjM262_Mg0Rpg)

## Локальный запуск

Вам понадобится:

- Linux
- Python 3.14 с модулем `venv`.
- Docker с Docker Compose.

1. Клонируйте репозиторий.

```bash
git clone git@github.com:paveltessman/licmgr.git
cd licmgr
```

2. Создайте виртуальное окружение, установите зависимости.

   ```bash
   python3.14 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   python -m pip install --no-deps .
   ```

3. Поместите в `.env` пару ключей X25519 и случайный пароль PostgreSQL.

   ```bash
   if [ ! -e .env ]; then
     (
       umask 077
       set -e
       keypair="$(licmgr keypair)"
       db_password="$(python -c 'import secrets; print(secrets.token_hex(24))')"
       printf '%s\nLICMGR_DB_PASSWORD=%s\n' "$keypair" "$db_password" > .env
     )
   fi
   ```

   | Переменная                  | Назначение                                                                    |
   | --------------------------- | ----------------------------------------------------------------------------- |
   | `LICMGR_SERVER_PRIVATE_KEY` | Закрытый ключ X25519 в Base64. Используется сервером для дешифровки запросов. |
   | `LICMGR_SERVER_PUBLIC_KEY`  | Соответствующий открытый ключ X25519 в Base64. Используется клиентом.         |
   | `LICMGR_DB_PASSWORD`        | Пароль PostgreSQL.                                                            |

4. Запустите сервисы.

   ```bash
   docker compose up --build -d
   ```

   Сервер доступен по адресу `http://127.0.0.1:8000`.

## Выпуск и активация лицензии

1. Чтобы было что активировать, выпустите хотя бы одну лицензию через CLI в контейнере приложения.

   ```bash
   docker compose exec -T app licmgr keys create --max-devices 1
   ```

   Команда вернет новый ключ лицензии.

2. Запустите клиент в том же виртуальном окружении, чтобы он имел доступ к зависимостям и прочитал публичный ключ из `.env`. Клиент сформирует идентификатор устройства и отправит зашифрованный запрос на сервер.

   ```bash
   python client/activate.py XXXX-XXXX-XXXX-XXXX
   ```

3. Проверьте последнюю строку вывода. При первой активации ожидается `Activated`. При повторной активации будет `Already activated`. При попытке активировать эту лицензию с другим идентификатором устройства сервер вернёт HTTP 409 с кодом `device_limit_reached`.

## Допущения и ограничения

- Клиент рассчитан на Linux. Для формирования идентификатора используется версия ядра, архитектурa CPU, число логических CPU и MAC-адрес из `/sys/class/net`. Изменение любого из этих значений, включая обновление ядра или смену выбранного сетевого интерфейса, может потребовать ещё один слот лицензии.
- Доставка открытого ключа сервера на клиент не реализована. Версионирование ключей тоже.
